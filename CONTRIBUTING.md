# Working on Ashen Crown

Two developers, one on **Windows** and one on **Linux**, share this repository. Everything
pushed to `main` is built and published automatically.

## One-time setup

The repository owner adds the other developer: **Settings → Collaborators → Add people**,
enter their GitHub username, and they accept the e-mail invite.

**Windows**
1. Install **Godot 4.3** (standard build, not .NET): https://godotengine.org/download/archive/4.3-stable/
2. Install **GitHub Desktop** (https://desktop.github.com), sign in, then
   **File → Clone repository → `jjcw1337-rgb/ashen-crown`**.
3. Open Godot, click **Import**, pick `project.godot` in the cloned folder, press **F5** to play.

**Linux**
1. Download Godot 4.3 for Linux (x86_64) from the same page, unzip it and make it executable
   (`chmod +x Godot_v4.3-stable_linux.x86_64`).
2. Clone with git:
   ```
   git clone https://github.com/jjcw1337-rgb/ashen-crown.git
   ```
   Pushing over HTTPS needs a GitHub sign-in: the easiest is the GitHub CLI
   (`gh auth login`), or a personal access token when git asks for a password.
3. Run Godot, **Import** `project.godot`, press **F5**.

The first open takes a minute while Godot builds its cache (`.godot/`, never committed).

## Using Claude on it

`CLAUDE.md` at the top of the repository tells Claude how the project works (commands, tests,
code map, gotchas). Either way works:

- **Claude Code on Linux/Windows:** clone the repo, open a terminal in it and run `claude`.
- **Claude on claude.ai:** connect GitHub (Settings → Connectors) with an account that has
  access to this repository, then ask Claude to work on `jjcw1337-rgb/ashen-crown`.

Claude can push to `main` like anyone else, so the same rule applies: run the tests first.

## Everyday workflow

1. **Pull first** (GitHub Desktop: **Fetch origin → Pull**; Linux: `git pull`) so you start from
   the latest version.
2. Make your change in Godot and play-test it with **F5**.
3. **Commit and push** (GitHub Desktop: write a summary → **Commit to main → Push origin**;
   Linux: `git add -A && git commit -m "what changed" && git push`).
4. About 4–5 minutes later the browser build and all three downloads are updated.
   Hard-refresh the browser page (Ctrl+F5) to see it.

Tips for two people:
- Pull before you start and push when you finish, so you rarely edit the same file at once.
- For a bigger experiment, work on a branch and open a pull request; only `main` publishes.
- If a push is rejected because the other person pushed first, pull, then push again.
- If a build fails (red ✗ in **Actions**), the site keeps the last good version; click the
  failed run to see the error.
- Line endings are handled by `.gitattributes`, so Windows and Linux editors don't fight.

## How the project is laid out

There are no art, sound or model files apart from the intro video (`assets/intro.ogv`).
Everything else is generated by code in `scripts/`:

| File | What it does |
|---|---|
| `game.gd` | Main loop: intro, zones, camera, graphics presets, saving, acts/difficulty runs, co-op wiring |
| `world.gd` | Builds each zone: terrain, roads, buildings, trees, grass, spawn points |
| `hero.gd` | The player character: class, movement, combat, skills, stats, gear |
| `wraith.gd`, `wraith_fx.gd` | The Wraith class's look and skill effects |
| `enemy.gd`, `projectile.gd` | Monsters, their AI and attacks |
| `data.gd` | **Most tuning lives here:** monsters, items, uniques, skills, acts |
| `items.gd` | Item generation, affixes, tooltips, enchanting |
| `ui.gd`, `hud_bar.gd` | Menus and HUD |
| `net.gd` | LAN co-op (host-authoritative, ENet) |
| `models.gd`, `skeleton.gd`, `flora.gd`, `props.gd`, `geo.gd` | Procedural 3D models |
| `mats.gd` | Shaders for terrain, props, cloth |
| `weather.gd`, `fx.gd`, `sfx.gd` | Snow/ash, particles, sound |
| `tools/` | Headless test scripts (not shipped) |

**Intro video:** replace `assets/intro.ogv` to change it. Godot only plays Ogg Theora, so convert
first, e.g. `ffmpeg -i trailer.mp4 -vf scale=1280:720 -c:v libtheora -q:v 7 -c:a libvorbis -q:a 5 assets/intro.ogv`.
Keep it under ~90 MB (GitHub's limit per file is 100 MB).

## Testing keys

- **F8** (or Esc → Testing panel): Immortal and One-hit kill switches, while `UNLOCK_ALL_ACTS` is on in `game.gd`.
- **F2**: sound on/off. **F3**: FPS counter.

## Godot's limitations (what to know)

- **Browser build:** WebGL only. No High/Ultra effects, no grass blades, no co-op (browsers
  can't open LAN connections), no intro video (download size), saves stay in that browser.
- **Co-op:** LAN only. Over the internet use Tailscale (host shares their Tailscale address) or
  a router port-forward of UDP 24567. Everyone must run the same version.
- **Engine:** no Nanite/Lumen-class rendering; smaller asset store than Unity/Unreal; C# can't
  export to the web; consoles need a third-party porting company.
- **Mac app** is unsigned: first launch needs System Settings → Privacy & Security → Open Anyway.
