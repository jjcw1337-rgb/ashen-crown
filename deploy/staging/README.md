# Ashen Crown staging

One DigitalOcean droplet (`ashen-crown-staging`, Ubuntu 24.04, NYC3, 161.35.185.195) runs the whole staging
backend. Production gets its own server and its own database later; nothing here is shared with it.

| What | Where | Port |
|---|---|---|
| Battlegrounds dedicated server (the game headless, Godot 4.3, systemd `ashen-crown-bg`) | `/opt/ashen-crown/staging/game` | UDP 24567, public |
| Online co-op server (the story game hosted online, `--server --coop`, systemd `ashen-crown-coop`) | same checkout | UDP 24570, public |
| Caddy, HTTPS for Nakama (Let's Encrypt IP certificate, short-lived profile, auto-renewed) | Docker `ashen-staging-caddy-1` | TCP 443 public, 80 for the ACME challenge |
| Nakama 3.41.0 (accounts, cloud characters, the stash; module `deploy/nakama/modules/ashen.lua`) | Docker `ashen-staging-nakama-1` | 7350 loopback only, console 7351 loopback only |
| PostgreSQL 16 (the STAGING database) | Docker `ashen-staging-postgres-1`, volume `ashen-staging_pgdata` | not published |

Secrets live only on the server, mode 600: `/opt/ashen-crown/staging/backend/nakama.env` (Postgres password,
Nakama server/session/refresh/http keys, console password) and `/opt/ashen-crown/staging/bg.env` (what the game
server needs to reach Nakama). They were generated by `setup.sh`; never copy them into Git, logs or chat.

Cloud firewall `8f3ea381-…`: SSH from Blaine's IP only; 80, 443, UDP 24567 and UDP 24570 from anywhere.

## Commands (from a machine with the `ashen-crown-staging` SSH alias)

```
ssh ashen-crown-staging 'sudo sh -s' < deploy/staging/setup.sh      # first time (safe to re-run)
sh deploy/staging/deploy.sh                                         # backend + game server, this checkout's HEAD
sh deploy/staging/deploy.sh --backend                               # only Nakama/Postgres/Caddy
ssh ashen-crown-staging 'sudo journalctl -u ashen-crown-bg -f'      # the game server's log ([BG] lines)
ssh ashen-crown-staging 'cd /opt/ashen-crown/staging/backend && sudo docker compose --env-file nakama.env ps'
ssh -L 7351:127.0.0.1:7351 ashen-crown-staging                      # then http://127.0.0.1:7351 = Nakama console
```

Checks against staging (the key is read on the server, never printed):

```
K=$(ssh ashen-crown-staging "sudo grep '^NAKAMA_SERVER_KEY=' /opt/ashen-crown/staging/backend/nakama.env | cut -d= -f2")
godot --headless --path . -s tools/nakama_check.gd -- https://161.35.185.195 "$K"
godot --headless --path . -s tools/bg_test.gd -- client 24567 addr 161.35.185.195 cloud https://161.35.185.195 "$K"
```

## Playing against staging locally

A staging build (from the `staging` branch's CI, later Steam's `staging` branch) already points here. A local run
can too: `user://env.cfg` with

```
[env]
env="staging"
bg_server="161.35.185.195:24567"
nakama_url="https://161.35.185.195"
nakama_key="<the staging server key>"
cloud="1"
```
