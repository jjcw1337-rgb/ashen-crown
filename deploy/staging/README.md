# Ashen Crown staging

One DigitalOcean droplet (`ashen-crown-staging`: `s-2vcpu-4gb`, 2 vCPU, 4 GB, Ubuntu 24.04, NYC3, 161.35.185.195,
$24/month) runs the whole staging backend. Production gets its own server and database later; nothing here is shared
with it.

| What | Where | Port |
|---|---|---|
| The lobby service (`deploy/lobbies/service.py`, systemd `ashen-crown-lobbies`): lobbies, and a headless match server per started match | `/opt/ashen-crown/staging/lobbies`, match servers from `/opt/ashen-crown/staging/server/current` | HTTPS through Caddy; matches on UDP 24600+ |
| Caddy, HTTPS (Let's Encrypt IP certificate, short-lived profile, auto-renewed) | Docker `ashen-staging-caddy-1` | TCP 443 public, 80 for the ACME challenge |
| Nakama 3.41.0 (accounts, raid join tickets, the admin role, telemetry; module `deploy/nakama/modules/ashen.lua`) | Docker `ashen-staging-nakama-1` | 7350 loopback only, console 7351 loopback only |
| PostgreSQL 16 (the STAGING database) | Docker `ashen-staging-postgres-1`, volume `ashen-staging_pgdata` | not published |
| Grafana (players, errors and logs, `docs/systems/telemetry.md`), Loki and Alloy (the server's logs) | Docker | Grafana at `/grafana/` behind Caddy |

Secrets live only on the server, mode 600: `/opt/ashen-crown/staging/backend/nakama.env` (Postgres password, Nakama
keys, console and Grafana passwords). They were generated by `setup.sh` and `grafana_setup.sh`; never copy them into
Git, logs or chat. There are **no backups** of the database yet (docs/PLAN.md).

## Deploying

```
sh deploy/lobbies/update.sh [--force] [ci-run-id]    # match servers + lobby service: the staging CI's server export
sh deploy/staging/backend.sh                          # Nakama module, compose file, Caddy, Grafana/Loki config
ssh ashen-crown-staging 'sudo sh -s' < deploy/staging/setup.sh   # first time only (safe to re-run)
sh deploy/staging/grafana_setup.sh                    # first time only: Grafana's passwords and read-only role
```

`update.sh` refuses while a match is starting or playing (restarting the lobby service ends it); `--force` ends it.
Clients come from the same CI run (the `staging` branch builds every platform and uploads to itch and Steam).

## Looking at it

```
ssh ashen-crown-staging 'sudo journalctl -u ashen-crown-lobbies -f'          # the lobby service
ssh ashen-crown-staging 'sudo ls /var/lib/ashen-lobbies'                     # match configs and logs (<id>.log)
ssh ashen-crown-staging 'cd /opt/ashen-crown/staging/backend && sudo docker compose --env-file nakama.env ps'
ssh -L 7351:127.0.0.1:7351 ashen-crown-staging                               # then http://127.0.0.1:7351 = Nakama console
```

## Playing against staging locally

A staging build already points here. A local run can too: `user://env.cfg` with

```
[env]
env="staging"
nakama_url="https://161.35.185.195"
nakama_key="<the staging server key>"
cloud="1"
```
