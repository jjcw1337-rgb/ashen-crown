# Retired features: what's hidden, what still depends on it, when it can go

The multiplayer overhaul (Blaine, 2026-11-06) retires features by switching them off in one place
(`scripts/mp_mode.gd`, `MpMode`) before deleting anything. Each row: what's off, where the switch acts, the code that
stays and why, and the condition for deleting it.

| Retired | Switch / where it acts | Code kept | Delete when |
|---|---|---|---|
| **Endless Waves** (the Last Flame) | `MpMode.WAVES = false`: the lobby browser offers no Waves mode or solo start (`LobbyClient`), the waypoints list no "vigil" activity (`Game.waypoint_activities`, `waypoint_activity_go`), the camp's Vigil Gate says it is sealed (`Game._interact` "vigil_gate"), and the lobby service refuses new Waves lobbies (`service.py` `LIVE_MODES`) | `vigil.gd`, `flame_board.gd` (the leaderboard), the Vigil zone in `World.build`, `match_instance.gd`'s waves branch, `Net`'s vigil RPCs (`vigil_feed`, `request_vigil`, `vigil_hi`) and the Nakama leaderboard | no save, test or tool loads the Vigil zone (its tests are gone since 2026-11-06) and nobody wants the mode back |
| **Create New Character** on the title | `MpMode.CREATE_CHARACTER = false`: the sidebar's button is hidden (`TitleHome._build_sidebar`) | the class picker (`UI._build_class_picker`, `ClassStage`), `UI._title_choose("new")` and character saves: single player's Enter World loads characters, and the Battlegrounds lobby's class choice reuses the class stage | single player gets its own way to make a character, or the old characters are migrated |
| **Lobby modes** other than Battlegrounds and Arena | `MpMode.MODES` (the game), `LIVE_MODES` (the lobby service) | `service.py`'s `MODES` capacity table keeps `waves` so a lobby made before the switch still finishes | no `waves` lobby in any state database |
| **Raiding with your own character** (the old Battlegrounds loop: your saved character went in, kept what it extracted, lost it all on death) | `MpMode.RUNS = true`: `Game.start_battlegrounds` always starts a fresh run character (`_start_run_raid`, `RunBuild`); the saved character is never loaded into a raid or written by one | `Game.strip_save`, `bg_strip`, `_bury_lost_raiders`, the save's `in_raid`, `bg_extracted`'s item count, `_bg_home_camp`'s messages | survivors (step 4) replace extraction rewards and no save has `in_raid` true any more |
| **The Battlegrounds stash** (the spawn chests' shared storage, `user://bg_server/stash.json`) | `MpMode.STASH = false`: `Battlegrounds.build` places no stash chests | `Battlegrounds._stash_chest`, `Net.sv_bg_stash` and the stash RPCs, `bg_page.gd`'s stash view, `SharedStash`, the Nakama stash functions | survivors are the only thing a run keeps and nothing reads the stash file |
| **Talents, level unlocks, stat points, gold, rings, amulets and the backpack in multiplayer** | `Hero.run` (a `RunBuild`) on a run character: `skill_locked`, `free_talent_points`, `_talents_changed` (passives instead), `recalc` (`RunBuild.GEAR` only), `add_to_inventory` (`_run_take`), `Game._run_pickup_ok`, `Game.run_rules` (loot) | all of it: single player still uses talents, unlocks, gold and the backpack | never (single player keeps them) |
| **The Hollow Crypt** (the old Battlegrounds map: rooms and corridors, antechamber gates, the floors below, the stash chests on daises) | `MpMode.FOREST = true`: `Battlegrounds.build` builds the Verdant Reach (`BgForest`) instead; `Battlegrounds.outdoor()` makes `Game.indoor`/`_zone_env` treat the raid as outdoors | the crypt half of `Battlegrounds.build`, `bg_floors.gd`, `crypt_props.gd` (A3's crypt uses its props), `_gate`/`gate_doors`, `stash_chests.gd`, `stash_dais.gd` (its tools were deleted 2026-11-06) | the forest map has played on staging a while and nobody wants the crypt as a second map (A3's crypt keeps `CryptProps`) |
| **Arena item stakes** (for now) | `LobbyClient.draw` hides "Play for items" while `MpMode.RUNS` (Arena members bring survivors, and `lobby_stakes.gd` escrows items out of single-player saves) | `lobby_stakes.gd`, the service's stake ops and receipts, `LobbyClient.collect` | survivors can stake their own items through server-held escrow (docs/systems/multiplayer_authority.md) |

Rules: hide the entry points and stop the execution paths first; delete self-contained code once nothing uses it;
no commented-out blocks; one row here per retired feature, removed when its code is.
